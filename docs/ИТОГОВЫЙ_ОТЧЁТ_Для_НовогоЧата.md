## 1. Что за проект

**FriendlyPoker** — браузерное приложение для дружеской игры в покер (не на деньги). Игроки создают клубы, приглашают друзей, садятся за столы и играют в Техасский Холдем.

### Стек

| Слой | Технологии |
|---|---|
| **Backend** | Java 21, Spring Boot 3.4, Spring WebSocket (STOMP), Spring Security + JWT, Spring Data JPA |
| **Frontend** | React 18 + TypeScript, Vite, Tailwind CSS, SockJS + STOMP.js |
| **БД** | PostgreSQL 16 (+ Liquibase миграции) |
| **Сборка** | Gradle (back), npm (front) |
| **Инфра** | Docker Compose (2 контейнера: app + postgres) |

## 3. Архитектура игрового движка

### Ключевые классы

| Класс | Назначение |
|---|---|
| `GameEngine` | Интерфейс: `createGame`, `addPlayer`, `startHand`, `processAction` |
| `GameEngineImpl` | Реализация: управление фазами, `shouldAutoResolve()`, `nextDealerIndex()` |
| `GameState` | Иммутабельный record: `players`, `phase`, `communityCards`, `pot`, `dealerIndex`, `currentPlayerIndex` |
| `PlayerState` | Иммутабельный record: `id`, `chips`, `status`, `currentBet`, `holeCards`, `hasActedThisRound` |
| `GameSession` | Синхронизированная обёртка над движком: `startHand()`, `processAction()`, `leavePlayer()` |
| `GameSessionManager` | `ConcurrentHashMap<Long, GameSession>` — хранит активные сессии по tableId |
| `GameService` | Spring-сервис: связывает HTTP/WebSocket с движком |

### Поток обработки действия

```
Browser (POST /action)
  → GameController.action()
    → GameService.processAction()
      → синхронный GameSession.processAction()
        → синхронный GameEngineImpl.processAction()
          → PhaseHandler.handle(state, action)
            → проверка isBettingRoundComplete / isOnlyOnePlayerLeft
            → advancePhase / handleLastPlayerStanding
          → цикл shouldAutoResolve() (авто-переход FLOP→TURN→RIVER→SHOWDOWN)
      → broadcast() (WebSocket рассылка)
      → finishGame() (сохранение в БД, только при FINISHED)
```

### Фазы игры
```
WAITING → PRE_FLOP → FLOP → TURN → RIVER → SHOWDOWN → FINISHED → WAITING
```
`isBettingPhase()` возвращает `true` для: PRE_FLOP, FLOP, TURN, RIVER.

## 4. Текущий статус: что работает и что сломано

### ✅ Работает
- Регистрация, логин, JWT-аутентификация
- Создание клубов, инвайты, роли (Owner/Admin/Member)
- Создание столов, посадка за стол
- Базовый игровой цикл Холдема (все 5 фаз + шоудаун)
- Оценка комбинаций (SevenCardEvaluator)
- Сайд-поты при all-in
- WebSocket real-time обновления
- Таймер на ход с авто-фолдом
- Сит-аут после 2 таймаутов
- Show Cards (показать сфолдированные карты после раздачи)
- Режим зрителя с возможностью сесть в любое время
- Ротация дилера
- Авто-рестарт после FINISHED (3 сек)

### ⚠️ Известные баги / недоделки
1. **Дилер и блайнды не всегда корректно вращаются** при добавлении/удалении игроков между раздачами
2. **Нет Омахи** (движок захардкожен на 2 карты)
3. **Нет PWA** (нельзя установить на телефон как приложение)
4. **UI не адаптирован под мобильные** (только десктоп)
5. **Нет кнопки «закрыть стол»** у Owner (бэкенд есть, фронтенд скрыт пока нет `myRole` в ответе)
6. **Авто-рестарт может задваиваться** если несколько staff-игроков
7. **`finishGame` вызывается без транзакции** для leaveTable (отсутствует `@Transactional`)

## 7. Ключевые архитектурные решения (не ломать!)

### 1. Иммутабельность GameState
`GameState` — Java record. Каждое изменение создаёт новый объект через `with*` методы. Это позволяет движку быть потокобезопасным без блокировок.

### 2. Синхронизация в GameSession
Все методы `GameSession` — `synchronized`. Два игрока не могут одновременно изменить состояние игры.

### 3. GameSession не удаляется после FINISHED
Сессия остаётся в `GameSessionManager` после завершения раздачи. При следующем `startHand()` проверяется — если состав игроков не изменился, сессия переиспользуется (дилер вращается корректно). Если изменился — создаётся новая.

### 4. playerIdInSession() вместо запросов в БД
Для определения ID игрока используется поиск по `displayName` в `state.players()` — без обращений к `userRepository`. Это исключает зависимость от HikariCP на горячем пути.

### 5. WebSocket broadcast без hole cards
`broadcast()` отправляет состояние с `viewer = null` → hole cards скрыты у всех. Свои карты игрок получает через REST (`getState` с viewer = playerId из JWT).

### 6. shouldAutoResolve() проверяет isBettingRoundComplete()
Не возвращает `true` слепо для betting-фаз. Проверяет, что все игроки походили и сравняли ставки, или все ALL_IN.

1. Очистить БД (команда в разделе 2)
2. Запустить бэкенд: `docker compose up --build -d`
3. Запустить фронтенд: `cd frontend && npm run dev`
4. В трёх окнах Инкогнито:
   - alex: зарегистрироваться → создать клуб → создать стол
