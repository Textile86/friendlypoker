# 🏆 Исправление: all-in → авто-шоудаун

> Дата: 08.06.2026

---

## Проблема

После того как оба игрока пошли all-in, игра не прокручивается автоматически до шоудауна. Фронтенд показывает панель действий «Your turn» для all-in игрока, и таймер тикает.

## Причина

`AvailableActionResponse.fromState()` на бэкенде не проверяет статус текущего игрока. Даже если игрок в `ALL_IN`, ему возвращается `yourTurn: true` с доступными действиями (CHECK, ALL_IN и т.д.).

Движок (`GameEngineImpl.processAction()`) содержит авто-разрешение фаз после того, как betting round complete. Но проблема в том, что бэкенд всё равно отдаёт `yourTurn: true` для all-in игрока, и фронтенд показывает панель действий.

## Исправление (фронтенд — сделано)

В `GamePage.tsx`:

1. **Панель действий скрывается для ALL_IN игроков:**
   ```tsx
   {actions?.yourTurn && myPlayer?.status !== 'ALL_IN' && (
   ```

2. **Таймер не запускается для ALL_IN игроков:**
   ```tsx
   if (myPlayer?.status === 'ALL_IN') { setTimeLeft(timeoutSecs); return }
   ```

Теперь после all-in обоих игроков фронтенд показывает «Waiting for opponent…» у обоих, и движок сам доигрывает раздачу через WebSocket-обновления.

## Рекомендация (бэкенд — ты)

В `AvailableActionResponse.fromState()` добавить проверку в начале метода:

```java
public static AvailableActionResponse fromState(GameState state, String playerId) {
    if (!state.phase().isBettingPhase()) {
        return new AvailableActionResponse(false, null, List.of());
    }

    PlayerState current = state.currentPlayer();
    
    // ADD THIS CHECK:
    if (current.status() == PlayerStatus.ALL_IN) {
        return new AvailableActionResponse(false, null, List.of());
    }
    
    boolean youTurn = current.id().equals(playerId);
    // ... остальной код
}
```

Это гарантирует, что бэкенд никогда не вернёт `yourTurn: true` для all-in игрока.
